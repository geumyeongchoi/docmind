# Git 브랜치 전략

## 브랜치
- `main`은 항상 배포 가능한 상태를 유지한다. 직접 push는 금지하며 PR로만 병합한다.
- 기능 브랜치는 `feat/<이슈번호>-<요약>`, 버그는 `fix/<이슈번호>-<요약>` 형식으로 만든다.
- 긴급 수정은 `hotfix/<요약>` 으로 main에서 분기하고, 배포 후 같은 커밋을 개발 브랜치에 반영한다.

## 병합
- 병합 방식은 **squash merge** 로 통일한다. 커밋 이력은 PR 단위로 읽힌다.
- 커밋 메시지는 Conventional Commits(`feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `chore:`)를 따른다.
- 병합 전 CI(빌드·테스트·정적분석) 통과가 필수이며, 실패한 상태로 병합할 수 없다.

## 태그와 릴리스
- 릴리스 태그는 `v<major>.<minor>.<patch>` 이며 배포 시점에 main에 단다.
- 하위 호환이 깨지는 변경만 major를 올린다.
