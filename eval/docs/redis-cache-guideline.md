# Redis 캐시 사용 가이드

## 키
- 키 형식은 `<서비스>:<엔티티>:<식별자>` 이며 콜론으로 구분한다: `catalog:product:12345`.
- 모든 키에 TTL을 설정한다. TTL 없는 키는 배포마다 늘어나 메모리를 잠식한다.
- 기본 TTL은 10분, 변경이 드문 마스터 데이터는 6시간을 권장한다.

## 패턴
- 조회 캐시는 cache-aside(읽기 시 채우기)를 기본으로 한다.
- 쓰기 경로에서 캐시를 갱신하지 말고 삭제한다. 갱신은 경합 시 오래된 값을 남긴다.
- 캐시 스탬피드 방지를 위해 TTL에 ±10% 지터를 준다.

## 금지
- `KEYS` 명령은 운영에서 사용하지 않는다. 필요하면 `SCAN`을 쓴다.
- 캐시를 유일한 저장소로 쓰지 않는다. 캐시가 비어도 기능이 동작해야 한다.
- 개인정보를 캐시에 원문으로 저장하지 않는다.

## 장애
- Redis 장애 시 애플리케이션은 캐시를 건너뛰고 원본 저장소로 폴백한다. 서킷 브레이커 임계값은 실패율 50%다.
