# 레거시 주문 시스템 기술 노트 (외식UP 채널)

작성 2026-06-11 · 갱신 2026-08-28 · 담당 주문플랫폼팀

## 한눈에 보기
- PRC_SOOROU001 프로시저는 레거시 채널의 주문 저장을 담당한다.
- Kafka 토픽 payment.card.events 는 알림톡 발송 컨슈머가 구독한다.
- 피처토글 order.write-mode 가 DUAL 이면 레거시와 v2 에 모두 기록한다.
- 주문 대사 배치는 매일 03:00 에 실행된다.

## 프로시저 PRC_SOOROU001
- PRC_SOOROU001 프로시저는 레거시 채널의 주문 저장을 담당한다.
- 주문 헤더, 주문 상세, 여신 차감을 한 트랜잭션으로 처리한다.
- 입력은 고객코드, 배송일, 상품 목록 JSON 세 가지다.
- 출력은 주문번호이며 형식은 `ORD-YYYYMMDD-NNNNNN` 이다.
- 실패하면 SQLSTATE 와 함께 전체 롤백된다.
- 오류 코드 E4012 는 여신 한도 초과, E4020 은 재고 부족을 의미한다.

## MSA 전환 (듀얼라이트)
- 2026년 6월부터 주문 저장을 Order Service v2 로 이관하고 있다.
- 피처토글 이름은 `order.write-mode` 다.
- 토글 값이 DUAL 이면 프로시저와 v2 에 모두 기록한다.
- 토글 값이 V2 이면 v2 에만 기록한다.
- 토글은 요청 진입점에서 한 번만 읽어 하위로 전달한다.
- 컷오버 후 6주간 v1 주문과 v2 주문이 공존한다.
- 대사 배치 `order-reconcile` 이 매일 03:00 에 실행된다.

## 결제
- 카드결제 승인과 취소 알림은 Kafka 토픽 `payment.card.events` 로 발행된다.
- 알림톡 발송 컨슈머가 이 토픽을 구독한다.
- 멱등키는 36자 UUID 형식이며 Order Service 계약을 따른다.

## 알려진 제약
- PRC_SOOROU001 은 단일 배송지만 지원한다. 분할 배송은 v2 에서만 가능하다.
- 레거시 채널은 부분 취소를 지원하지 않는다.
