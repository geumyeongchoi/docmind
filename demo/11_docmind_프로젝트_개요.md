# docmind — 사내 문서 RAG 챗봇 프로젝트 개요

작성자 최금영 · 최종 갱신 2026-09-08 · 저장소 https://github.com/geumyeongchoi/docmind

## 0. 한눈에 보기
- docmind 는 업로드한 문서만 근거로 답하는 사내 문서 RAG 챗봇이다.
- 근거를 못 찾으면 LLM 을 호출하지 않고 "제공된 문서에서 찾지 못했습니다" 라고 답한다.
- 검색은 벡터 검색과 전문검색을 합친 하이브리드이며 RRF 로 병합한다.
- 프롬프트 인젝션은 컨텍스트 중화와 출력 후처리 두 단계로 막는다.
- 모델은 private, public, claude 세 프로파일로 전환한다.

## 1. 무엇을 푸는 프로젝트인가
- 사내 규정과 기술 문서는 Confluence, PDF, Markdown 으로 흩어져 있다.
- 기존 검색은 키워드 일치라서 "연차는 이월되나요" 같은 자연어 질문에 답하지 못한다.
- 문서를 외부 LLM 으로 보내는 것을 금지하는 조직이 많다.
- docmind 는 업로드한 문서만 근거로 답하고, 근거가 없으면 찾지 못했다고 답한다.
- 답변에는 항상 출처(문서명, 페이지, 유사도)를 붙인다.

## 2. 기술 스택
- 언어와 프레임워크는 Kotlin 2.2, Spring Boot 3.5, Spring AI 1.1 이다.
- 벡터 저장소는 PostgreSQL 17 + pgvector 이며 HNSW 코사인 인덱스를 쓴다.
- 문서 파싱은 Apache Tika 를 사용해 PDF, DOCX, MD, TXT 를 처리한다.
- 채팅은 SSE 스트리밍이며 이벤트 순서는 citations, token, redact, done 이다.
- MCP 서버로 search_docs 와 ask_docs 툴을 노출한다.

## 3. 모델 프로파일
- private 프로파일은 Ollama 로컬 모델을 쓴다. 데이터가 서버 밖으로 나가지 않는다.
- public 프로파일은 OpenAI 를 쓴다. 임베딩은 text-embedding-3-small 이다.
- claude 프로파일은 Anthropic 을 채팅에만 쓰고 임베딩은 로컬 bge-m3 를 재사용한다.
- 프로파일 전환은 `--spring.profiles.active` 한 줄이며 소스 변경이 없다.
- private 과 public 은 임베딩 차원이 1024 와 1536 으로 달라 벡터 테이블을 분리한다.

## 4. 핵심 설계 결정
- 검색은 벡터 검색과 PostgreSQL 전문검색을 병렬로 돌리고 RRF 로 병합한다. k 값은 60 이다.
- 검색 결과가 없거나 최고 점수가 임계값 0.35 미만이면 LLM 을 호출하지 않는다. 비용과 환각을 함께 줄인다.
- 도메인 패키지는 Spring 을 import 하지 않는다. ArchUnit 테스트로 강제한다.
- 청킹은 토큰 기준 600, 오버랩 80 이며 오버랩 분할기를 직접 구현했다.
- 세이프가드는 사용자 질문에만 적용한다. 프롬프트 전체를 검사하면 인젝션 문구가 든 문서 때문에 정상 질문까지 거절된다.

## 5. 프롬프트 인젝션 2단 방어
- 1단계는 컨텍스트 중화다. 검색된 청크에서 모델에게 지시하는 문장만 자리표시자로 바꾼다.
- 문서를 통째로 제외하지 않는다. 같은 문서의 정상 문장이 다른 질문의 근거로 남아야 하기 때문이다.
- 2단계는 출력 후처리다. 답변이 제거된 지시문과 12자 이상 일치하면 폐기한다.
- 지시문 안에 따옴표로 심긴 미끼 값이 답변에 등장해도 폐기한다.
- 폐기는 SSE redact 이벤트로 알리며 수신 측은 그때까지 받은 토큰을 버린다.

## 6. 한계와 다음 과제
- 한국어 전문검색이 simple 사전이라 조사가 붙은 어절을 놓친다. pg_bigm 전환이 다음 과제다.
- 문서별 접근 권한 제어와 멀티 테넌시는 아직 없다.
- 이미지 OCR 은 지원하지 않는다.
